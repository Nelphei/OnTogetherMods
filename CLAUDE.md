# On-Together mods

BepInEx 5 plugins for On-Together (GigaPuff), a Unity 6 (6000.0.60) **Mono** game. Multiplayer runs on PurrNet over Steam lobbies, with Vivox voice.

## Layout
- `Directory.Build.props`: shared settings for every mod. Targets netstandard2.1, sets the game path (`GameDir`), and references BepInEx, HarmonyX and every game/Unity DLL with `Private=false`.
- `Directory.Build.targets`: when built with `-p:DeployToGame=true`, copies the DLL and PDB to `<GameDir>\BepInEx\plugins\<AssemblyName>\`, plus the files in the mod's `Content\` folder if it has one (flat, no subfolders; unchanged files are skipped). Normal builds don't touch the game.
- `HelloTogether/`: starter mod (a logging plugin plus one Harmony postfix). Copy it to start a new mod, change the GUID and names, delete its `<NoDeploy>true</NoDeploy>` line (it keeps the template out of the game when deploying), then `dotnet sln add`.
- `PhotoMode/`: free camera, UI hiding and PNG screenshots (F9 to toggle). Works only in the Normal window mode.
- `EmoteSync/`: players who turn it on (F7) start emotes together on the same network tick, and join each other's free-focus activities with loops kept in step (a busy player joins once free, for up to 30 s, or at once with a "Join now" button). Every player in the group needs the mod.
- `TeleportSpots/`: a window (F5) where you save the spot you're standing on and click a name to teleport back there. Spots are saved in `BepInEx\config\TeleportSpots.json`. Only you need the mod.
- `SongPlayer/`: plays .mid files on the instrument you're sitting at. Its window appears by itself at an instrument. Songs go in `Music\On-Together`. Other players hear the song without the mod.
- `TraceOverlay/`: while you draw on a chalkboard or whiteboard, lays a see-through picture over the board to trace. Its window appears by itself while drawing. Images go in `Pictures\On-Together\Trace`. Only you see the picture.
- `FocusAnywhere/`: the focus key opens the free focus menu on any ground or in the air (you stop there and focus floating), and that menu lists every activity in the game (land, water and seat-spot ones). Seat spots keep their own menu. Its icon switches the whole mod off and on; switched off, it writes the game's own activity lists back once you're not focusing (`ActivityList.Restore`). Right-clicking the icon opens the objects window (`ObjectsWindow`): Show all / Hands only / Hide all, a box per group (`Part`: desk, placed, hands, headphones, floaties, Zzz; `Parts.Classify` goes by where a prop sits: under the `AvatarArmature` skeleton = carried, under `mixamorig:Head` = headphones), exceptions for single objects of the current activity (`Choices`, the `[Objects]` settings, keyed by GameObject name), other activities' objects added to the current one ("Add item...", `[Objects] Added`, kept per activity as `FocusType/AnimState`, e.g. `Read/12`; they always show, sit where their own activity has them, and the game switches them off with the rest at stand-up or activity change; the easel is left out), and the game's own floatie spin and camera turning settings (`Game.SetFloatieSpin` / `SetCameraTurning`). Right after `SetFocus` (top priority, before other mods' postfixes; its own floater-on-land postfix runs just before), `NoObjects` notes the desk, floatie and props the game switched on and switches off the unticked ones, which shows for everyone (see the personal desk note); hiding the desk clears `IsDesk` so the pet doesn't sit on it. Switched off, everything shows again and added objects don't. Known issue (left alone on purpose, 2026-11-16): sleeping at a hidden desk, the Zzz (`fx_SleepDesk`) don't show even when ticked; nothing in the game files links them to the desk. Only you need the mod.
- `DeskSnap/`: when you sit at your desk near someone else's, moves you beside it, facing the same way, at exactly their height (so rows stay level, even in the air), with a small gap (or to the end of the row). F3 turns it on/off, and while sitting also snaps you or moves you back. Also snaps after an EmoteSync focus join. Only you need the mod.
- `ChatRange/`: a small box just above the chat box (beside it if there's no room) listing who's in range of your local chat messages. Shows while the chat box is open on its Local tab. Not in the PanelStack stack, since it follows the chat box. Only you need the mod.
- `NameDesigner/`: a window (F4) to colour each letter of your player name or a session name, with a TextMeshPro preview and 5 preset slots per tab (saved in `BepInEx\config\NameDesigner.json`). On the main menu it opens by itself beside the Create Session box and writes the design straight into it. A player name can also colour the colon after it in chat: the name ends with `</color><#colon>`, which closes chat's player colour and leaves the colon colour open for the game's own `:</color>` (see `Design.ToRichText`; text the game puts after a name elsewhere takes that colour too). In a world, Session Manager's Design button opens the Session tab beside its window and the design goes into Session Manager's name box (`Shared/SessionNameLink.cs`). Card Designer's Design name button opens the Name tab beside its window, and it closes with it (`Shared/NameDesignerLink.cs`). Only you need the mod; everyone sees the colours.
- `CardDesigner/`: a window to style the ID card's lines (date of birth, horoscope, location, area of study, quote) like a word processor: B/I/U/S, colour (gradient, rainbow), highlight, size, align, clear, undo/redo, a Code view, emoji and symbols, 5 presets (`BepInEx\config\CardDesigner.json`). Opens from its icon (no key by default) or a **Design card** IMGUI button drawn over the ID card page's unused `Button_Next` slot (`Game.CardButtonBounds`); opened that way it closes with the page. The typing box is a `TMP_InputField` subclass (`CardInputField`: rich text on, tag editing off, so the caret skips hidden tags; it types nothing while Ctrl is held, so the window's Ctrl+B/I/U/Z/Y shortcuts don't type a tab or new line) on the mod's own canvas (`CardCanvas`, which also draws the window box, the card preview and the popup box, since IMGUI always draws on top of uGUI). A toolbar action turns the caret range into text positions with `textInfo.characterInfo[i].index`, restyles those pieces with `RichText` (reads TMP's tags the way TMP does: b/i/u/s counted, color/mark/size stacked, each kind separate so tags needn't nest, tags it doesn't edit kept in place, non-tags like `<3` as letters; writes the fewest tags, `<#RGB>` colours, tags left open at the end) and sets the text back with the same caret positions (restyling never changes the shown letters). The preview is built in the card's own units at the viewer card's box sizes and settings, scaled down, and cuts the quote at 3 lines like the game. Apply does `CloseIDCard`'s job for those lines (`Game.ApplyCard`). The name line opens Name Designer beside the window (`Shared/NameDesignerLink.cs`). Only you need the mod; everyone sees the card.
- `OutfitSlots/`: outfit slots 4-9 on top of the game's 3, as extra rows in the outfit screen's style list (copied from row 3), plus a quick-swap window (F2; right-clicking the icon wears the next slot). Slots 4-9 are saved in `BepInEx\config\OutfitSlots.json`, and the game's own save only ever sees slots 1-3 (see the outfits note). Stays off while BlueSage QoL's own style slots 4-9 are on (`EnableExtendedAvatarStyles`), and copies them on its first run. Only you need the mod; everyone sees the outfit.
- `QuickHide/`: in split screen and mini mode, a key (F10) or its icon makes the whole game window invisible and click-through (world, characters, all UI), and the key brings it back, even while another app is focused (read with `GetAsyncKeyState`, Windows only). Hiding from inside the game hands the keyboard to the next app window down (`Win32.FocusWindowBehind`), so typing doesn't reach the hidden game. Picking the game in the taskbar or Alt+Tab, switching window modes or leaving the world shows it again. Does nothing in Normal mode. Only you need the mod.
- `NetworkCrashFix/`: stops a crash in PurrNet's packet reader (see the crash files note). Prefixes on `BitPacker.ReadBitsWithoutChecks` (which `ReadBits` and `ReadBytes` call) and `ReadBits` read byte by byte when within 9 bytes of the array's end, with bytes past it counted as 0; everywhere else the game's code runs. Before patching it compares its reader with the game's for every start bit and bit count, and stays off on a mismatch; after patching it checks `ReadBits` and `ReadBytes` really go through it. Always on: no key, no in-game icon and no on/off setting (removed in 0.1.1; `Settings` deletes the old `Enabled` / `ShowIcon` lines from the .cfg). Its `Icon.cs` isn't compiled and is only there for the Thunderstore icon. Only you need the mod.
- `DeskSwarm/`: a window (F11) to fly your seated desk (`Flight.Pilot`: movement keys camera-relative, Space up, Shift down, tilt into the motion) and to lead or join swarms. Followers' desks fly to their spot in the leader's formation (10 flying shapes, and 5 landing ones (`Formations.Lands`) where `Flight.GroundUnder` puts each spot on the ground and desks hop up while far from it; `Formations.Place`), worked out on each follower's own screen from the leader's pose, their place in the leader's list and the shared tick clock. Membership goes over Steam lobby chat like EmoteSync (tag `OTDS1`; only the leader changes a swarm and sends it whole as `SWARM`). Moves only free-focus sitters (not seat spots), always your own character, through `Game.MoveSeated`. While flying, the stand-up key is blocked (`InputPatch`) and the game's camera drift is off. The `ThroughBuildings` switch (window, on by default; the leader's goes to followers as `THRU` in `SWARM`) makes the floor check see only land and water (`Flight.IsLand`: the Water layer, colliders at least 2 m wide reaching below y -1 into the sea, or named Ground/Island/Hill/Mountain/Shore). The game has no ground layer or tag; its scene keeps land under `Island/IslandGround`, buildings under `Island/Buildings` (plus 3 hills), bridges under `Island/Decks&Bridges`. Standing up away from the sit spot sends the missed trigger exits (`AreaExits`). Only you need it to fly; everyone in a swarm needs it.
- `SessionManager/`: tools for the session's host (crown icon, greyed out for everyone else; no key by default). Window tabs: Session (name with a Name Designer Design button, player cap, Public/Private, Ask to join, Locked = `SetLobbyJoinable`, the 5 social tags, Steam invite, a saved setup), Players (who's here and who left, from `PlayerLog`; Kick = the game's `BanRPC` without adding to its ban list; Ban for 1 hour/day/week or forever = the game's ban list, with lengths and notes in `BepInEx\config\SessionManager.json`; anyone still connected 5 s later is dropped with PurrNet's `playerModule.KickPlayer`), Requests (the game's `LobbyRequestManager` queue, answered from the window or by rules: friends, away, locked) and Bans (unban, Steam ID, note). Timed bans end in any scene, but only after the game has read its ban file (`Game.BansLoaded`, set by a `DataManager.LoadBanData` postfix or by being in the world). The Create Session picker (`MultiplayerManager.ChangeFilterPlayer`) goes past 16 up to `MaxPlayers` (128), and is left alone when a PlayerLimitLift mod is loaded (`Lift`, which then takes that mod's `MaxLobbySize`). Sessions over 16 are untested. `Icon.cs` also keeps two other icons Soapy liked (`Icon` setting). Only the host needs it.
- `DoomTogether/`: plays DOOM in a window (demon icon, no key by default; GPL-2.0, see below). `Engine\` is Managed Doom's `ManagedDoom/src` minus `Silk\` (sinshu/managed-doom master 9365696, 2025-11-24; GPLv2), changed only in `ConfigUtilities.cs` (`DataDirectory`, where saves go) and `Doom/Menu/SaveSlots.cs` (no `Stream.ReadExactly` in netstandard2.1), each with a dated note at the top. `MeltySynth\` is sinshu/meltysynth 4ba079c (MIT), unchanged. `Content\` ships beside the DLL: freedoom1.wad and freedoom2.wad (Freedoom 0.13.0, BSD), TimGM6mb.sf2 (from Managed Doom v2.1a's release, GPLv2) and the licence texts. The mod's own files are the Unity front end: `UnityVideo` (the renderer writes column by column, so the texture is the picture on its side, `Renderer.Height` wide; `DoomWindow.DrawTurned` turns it back with a GUI.matrix rotation), `UnitySound` (AudioSources, OpenAL position turned into `panStereo`), `UnityMusic` (MeltySynth on the audio thread in `OnAudioFilterRead`, beside an AudioSource looping silence), `UnityUserInput` (keyboard only; F keys aren't passed on, other mods use them), `DoomHost` (35 tics a second, drawn twice a tic with `video_fpsscale` 2; `Freeze` stops it with its sound). DOOM has the keyboard (`DoomWindow.HoldsKeys`: the `IsCancelInputs` patch plus Enter, like chat) from opening the window or clicking it until a click elsewhere (icon row excepted), chat or a game menu; without it DOOM freezes (`PauseWithoutKeys`). Opening while standing and free starts the handheld console (`PropType.GameDeck`, filed under `FocusType.Connect`: land animation 8 with the personal desk, water 110 on the floatie; free focus never uses `Play`) like Emote Sync's FocusJoin (`Gaming.TrySitDown`); already sitting changes nothing and closing never stands you up (Soapy wanted it to fit with Desk Swarm, which stops flying on `IsCancelInputs` anyway). Closing the window keeps the game frozen; DOOM's Quit ends it. The window sits in the PanelStack stack until you drag its title row (`HandleDrag`, after the header buttons so they keep their clicks); then it stays where you left it (`WindowX` / `WindowY`, 1080p units, saved on release, kept on screen), and a double-click puts it back in the stack (-1). The speaker header button (`IconButton`, pixel pictures in `DoomWindow`: two waves, one, a cross at 0) opens a volume slider (`DrawVolumeMenu`, also scroll in steps of 5); the value lives in `_volume`, which the sound and music read live, and goes to the `Volume` setting only when the slider closes. The **?** header button shows a controls card over the picture (`DrawControls`; arrow keys spelled out, since IMGUI's font may lack arrow glyphs), also by itself on the first open (`ControlsSeen`); DOOM is frozen while it shows, and the key that closes it isn't passed to DOOM. IWADs come from `Documents\On-Together\Doom` (`WadFolder`) and the mod folder, by DOOM's own names (`ConfigUtilities.IsIwad`); PWADs aren't supported. Saves go in `BepInEx\config\DoomTogether\saves\<wad>`, DOOM's options in `managed-doom.cfg` beside them. A WAD's DEHACKED patch changes Managed Doom's static tables (`DoomInfo`, `DoomString`) for good, so `DoomInfoReset` copies them before the first game and puts them back before each new one (checked outside the game: Freedoom's level names go back to DOOM's). No game type clashes with the engine's names today (checked against every global type in the game's DLLs: only `PlayerState`, which the engine's own namespace wins); a new global type named like a `System` type the engine uses would break the build. Only you need the mod.
- `CardTable/`: card games in a window (cards icon, no key by default), one tab each in the title row (`Game` setting): Solitaire (Klondike) and Go Fish. `Solitaire` is the rules with no Unity (lists bottom first; `Pile(PileId)`; `FaceDown[i]` cards at the bottom of each tableau pile; a pile's top card is always face up; Undo keeps whole snapshots and counts as a move; `BestMove` is click-to-move: up top first, then piles with cards, then empty ones, never a king already at the bottom; `AutoFinishWins` tries Auto-finish on a copy, since drawing three it can get stuck, and the button only shows when it would win). `CardPixels` is the pixel art (also no Unity: `Picture`, 0xRRGGBBAA, icon palette; 32 x 44 cards, rank and suit side by side in the corner so overlapped piles read, original J/Q/K busts) and `CardArt` turns it into point-filtered textures. Both were checked outside the game with a .NET 8 console program that compiles those files, plays random games and renders the art to PNG. `TableWindow` lays the table out in screen pixels at a whole number of screen pixels per art pixel (`Size` Medium = 2, Large = 3 at 1080p, stepping down if it doesn't fit) and converts to 1080p units only for PanelStack and `WindowX` / `WindowY`; every change goes through `Change()`, which notes where each card shows, applies the move and slides the cards that moved. Board clicks act in the OnGUI event, buttons in Update. The Solitaire game in progress and both games' stats are in `BepInEx\config\CardTable.json` (Json.NET, written to a .tmp and swapped in). **Go Fish** (tables of 2-6, computer players in the empty seats): `GoFish` is the rules (no Unity; `Ask` does a whole move: hand-over or fish, books, and `Settle` moves the turn on: an empty hand draws one on its turn or sits out once the pond's empty, and a player nobody can be asked by draws one and passes), with numbered `FishEvent`s for the log, animations and bots. `GoFishBot` remembers asks and "Go fish" answers but notices only 85% and forgets 8% a turn, and asks for the rank it holds most of (asking for the likeliest rank did worse outside the game; it wins about 54% of 2-player games and 83% of 4-player games against random askers). `GoFishHost` is the table you start (you're seat 0): it runs the rules and bots (1.3-1.9 s a move), gives a quiet player a computer move after 45 s when 2+ people sit, and sends each other player a `GoFishView` (one line of text, `Encode` / `Decode`) with only their own cards, after every change and every 15 s. `GoFishClient` is a table you joined. `GoFishTables` holds the one table you're at, and the others in the session from `TABLE` announcements. Players join by taking a computer player's seat, cards and all, and a computer player takes over a leaver's seat; the host closing, or leaving the session or the world, ends the table. Messages (`CardNet`, tag `OTCT1`): lobby chat for `TABLE` / `CLOSED` / `HELLO`; Steam P2P on channel 4207 for `JOIN` / `LEAVE` / `ASK` and `VIEW` / `FULL` / `GONE`, so hands only go to their owner. All of that but `CardNet` was checked outside the game: random games with invariants, bots, view text round trips, and a simulated session of four players' `GoFishTables` (joins, leaves, a quiet player, closing, a full table, an unreachable one), where every player's view matched the host's. `GoFishBoard` draws the tab: the table list, then the table laid out like the mock (opponents along the top in turn order after you, the pond on the left, the log on the right, your hand along the bottom; click a card to pick its rank, then a player). Names go through `RichName`, which turns TextMeshPro name tags into IMGUI rich text (colour, bold, italic kept, other tags dropped, a stray `<` swapped for a look-alike), since the table is IMGUI textures and would cover a TextMeshPro canvas. The icon gets a dot while it's your turn with the window closed. Mouse only and doesn't touch the character. Only you need the mod for Solitaire; everyone at a Go Fish table needs it.
- `BuddyUp/`: pair up with a friend (buddies icon, no key by default), then ride on their head, walk with them and sit down beside them. Being buddies is two-way (`Buddies`: ASK / YES / NO / BYE over Steam lobby chat, tag `OTBU1`; HELLO is answered with HERE plus your current RIDE / FOLLOW / SIT, and a HELLO from a buddy ends it, since they restarted). **Riding** (`Riding`): standing, you sit in the riding activity first (`Sitting.SitToRide`: `RideActivity` Meditate, `RideChoice` 0 = the first without desk, held prop or floatie; ground rules skipped, since you're moved straight up; `Sitting.ForRide` keeps it from sending SIT); already sitting free, you keep it. Every frame your game puts you at the buddy's `mixamorig:Head` + `RideHeight` with their yaw (`Game.PlaceSeated`) and keeps the stand-up spot (`_preFocusPosition`) on the ground beside them, so Space hops you off there; Get off / Shake off / buddy ended put you down there still sitting. Every modded game also glues every rider it knows of (RIDE messages) onto the head locally, bottom of each stack first (`Riding.Glue`), only while the network has the rider within 3 m of it, in `LateUpdate` (the controller's `[DefaultExecutionOrder(-500)]`: after Updates and animations, before Cinemachine) and again in `Application.onBeforeRender` (PurrNet's `NetworkTransform` sets remote players' positions in Update, LateUpdate or LateLateUpdate per its `_interpolationTiming`). Players without the mod see riders one network hop behind. No loops (can't ride anyone riding you); Desk Swarm piloting (`DeskSwarm.Flight.IsPiloting`, by reflection) gets you off. **Walking** (`Following`): `InputPatch` (an `InputManager.Update` postfix) hands the game `Horizontal` / `Vertical` turned into camera space (`PlayerFollower` yaw), so the real walk, stairs and swimming run; only when your own axes are 0, `LockState` is Free and nothing cancels input, never mid-emote; stuck = jump (`IsSpaceKeyDown`) twice, then hop (`Game.Hop`, TeleportSpots-style), also past `CatchUpDistance`. Beside: followers of one buddy take slots by Steam ID, right then left, further out each pair (behind them if a wall's in the way); Behind: points along the buddy's recorded path. Both walking with each other: the lower Steam ID stops. **Sitting together**: your SetFocus postfix sends SIT type/anim/desk (or SIT SEAT) to buddies, UP on standing; a follower walks to the spot beside them (desk 1.25 m, else 0.85 m, their height) and sits in the same activity (`Sitting.Sit`, the game's free-focus checks unless Focus Anywhere's AnyGround), placed exactly unless Desk Snap is on and it's a desk activity (Desk Snap snaps in its own SetFocus postfix); a buddy switching activity is followed while you're still in the one you joined. Moving a sitter sends the missed area exits at stand-up (`SitTracker` + `AreaExits`, like Desk Swarm). You and your buddy need the mod; everyone sees it.
- `Shared/`: source files compiled into more than one mod, each project adding them with `<Compile Include="..\Shared\X.cs" Link="Shared\X.cs" />`. `PanelStack.cs` stacks each mod's window along the bottom, right edges lined up 15% in from the right (clear of the chat box). Call `PanelStack.Place(id, order, size)` every OnGUI, skip drawing while `PanelStack.Hidden` is true (Photo Mode is taking a photo, or the game's eye button has hidden its UI; see the window modes note), and add an order constant for each new mod. `ClickBlocker.cs` is the invisible game-UI blocker that goes under a mod window (see the last game note). `IconBar.cs` puts each mod's 16 x 16 pixel-art icon (the mod's own `Icon.cs`, one palette letter per pixel, palette in `IconBar.cs`) in a row in the bottom-right corner: click does the mod's key, right-click a second action, hover shows name and key, a green dot means on and greyed out means off. Each mod (all but NetworkCrashFix) calls `IconBar.Draw(...)` first thing in OnGUI every frame, acts on the returned click in Update, calls `IconBar.Patch()` in `Plugin.Awake` (the first mod to load patches input for all of them), and has a `ShowIcon` setting; add an order constant for each new mod. `Draw` only notes the icon (picture, state, tooltip parts) in AppDomain data and hands back clicks: one host object (`IconBarHost`, made by the copy with the newest `HostVersion`) lays out and draws the whole row from its own OnGUI at `GUI.depth` -150, so a change reaches every mod once any one mod has it; bump `HostVersion` whenever the file changes how the row looks or behaves. The tray button (`TrayPixels`) sits at the right end: click opens the tray of tucked-away icons, right-click or Arrange icons starts arranging (drag to reorder or move between row and tray, click to tuck away or put back, Reset, Done), saved in `BepInEx\config\IconRow.json` (`Row` and `Tray` id lists; ids not listed go in by their order constant, ids of mods not drawing keep their place). Copies from before the tray draw their own icon from the old `Icons` table, which the host keeps writing (its icons take their mods' usual order numbers between them, in the arranged order, and the tray button 1000), so those line up but can't move. The row shows only in the world while no game menu is open (see the menus note) and Photo Mode is off (it calls `IconBar.HideRow()` every frame), has its own click blocker (row and tray), and PanelStack lifts the windows above it when it reaches under them. Mods without a key (SongPlayer, TraceOverlay, ChatRange, FocusAnywhere) use their icon as a remembered on/off switch (`Enabled`). `TextBox.cs` is a dark text box drawn with TextMeshPro on its own canvas, for any mod text with player names in it (see the player names note); `PlayerNames.cs` gets names ready for it. `SessionNameLink.cs` lets Name Designer read and write Session Manager's name box and Session Manager open Name Designer (AppDomain data, built-in types only, so either works alone). `NameDesignerLink.cs` lets Card Designer open Name Designer's Name tab beside its window (each shares its window rect, and Card Designer moves over to make room). `ColorPicker.cs` is the IMGUI colour square and hue strip both designers use.
- `Thunderstore/`: `pack.py` makes a Thunderstore zip per mod in `Thunderstore\bin\` (`python Thunderstore/pack.py [Mod ...]`, or the "package for Thunderstore" task). It does a clean Release build with no PDB path, renders `icon.png` from the mod's `Icon.cs`, adds the files in the mod's `Content\` folder beside the DLL, builds `README.md` from the mod's row and section in the repo README (with icon and `ShowIcon` notes only if the .csproj compiles `IconBar.cs`), and stops if the version in the .csproj, Plugin.cs and the changelog don't match, or if your Windows user name is in any file. Package names, descriptions, team and BepInExPack dependency are in `mods.json`; each mod's changelog is `changelogs\<Mod>.md`. A new mod needs an entry in both. `upload.py` uploads a zip through Thunderstore's API (`python Thunderstore/upload.py <zip>`), in the same steps as Thunderstore's own CLI: `usermedia/initiate-upload/`, a PUT per part to the storage host (DigitalOcean Spaces), `finish-upload/`, then `submission/submit/` to community `on-together`, category `mods`. It needs a team service account token from `THUNDERSTORE_TOKEN` or `.thunderstore-token` in the user folder (never in the repo), retries each part, and prints the server's full answer when a step fails; `--no-submit` uploads without publishing. The website's upload page gave up on Doom Together's 26 MB zip, because the connection to the storage host sometimes drops and the page doesn't retry.
- `Installer/`: `Install.ps1` (Windows PowerShell 5.1 or newer) installs r2modman (its newest GitHub release's setup, checksum checked, run with `/S`, per-user) unless it's there, then puts every non-deprecated SoapieScripts package on Thunderstore (newest versions, plus what they depend on) in the r2modman profile `SoapieScripts` for On-Together (`%APPDATA%\r2modmanPlus-local\OnTogetherVirtualCoWorking\profiles\`). It does what r2modman's own installer does: unzips each package to `cache\<package>\<version>`, copies BepInExPack's `BepInExPack\` folder to the profile root and other packages by the game's install rules (loose files to `BepInEx\plugins\<package>\`), and writes `mods.yml` entries like r2modman's. Other mods' `mods.yml` blocks are kept as text, a mod switched off in r2modman stays off (`.old` files), and mods already at the newest version aren't touched. It installs what's on Thunderstore, not the repo's builds. Options: `-Skip`, `-NoR2modman`, `-NoLaunch`, `-ProfileName`, `-DataFolder` (test with `-NoR2modman -NoLaunch -DataFolder <scratch folder>`). `Install.cmd` runs the `.ps1` beside it, or the copy on GitHub if it's alone, and uses no labels so LF line endings don't break it. `install-mac.sh` (bash 3.2, run with `curl ... | bash`) installs r2modmac (Zard-Studios/r2modmac, newest release's `r2modmac_macos_<aarch64|x86_64>.dmg` picked by `hw.optional.arm64`, sha256 from the GitHub digest, mounted with `hdiutil`, `ditto` into /Applications or ~/Applications, `xattr -cr`) and saves `SoapieScripts.r2z` in Downloads: a zip with `export.r2x`, r2modman's export layout (`profileName`, `mods` of `name` + `version` {major, minor, patch} + `enabled`) listing BepInExPack and every SoapieScripts package at its newest version. It doesn't write r2modmac's own `profiles.json` (a large front-end format that changes often): the player imports the file (Import Profile, Select .r2z or .zip file, MacOS, Import), r2modmac resolves each pinned version on Thunderstore (and aborts the whole import if one is missing), then Apply to Game downloads them. Dropping a `.r2z` onto an open profile adds its mods to that profile. JSON is read with JXA (`osascript -l JavaScript`, the script's `helper.js` heredoc), since Macs may not have Python. Tested only in Git Bash with stand-ins for `osascript` (the JXA run under Node with a `$.NSString` shim), `hdiutil`, `ditto`, `open`, `xattr` and `zip`.
- `reference/Assembly-CSharp/`: the game's code decompiled with ilspycmd, one file per class. It's gitignored and must never be published. Re-generate after a game update:
  `dotnet ilspycmd -p -o reference/Assembly-CSharp -r "<Managed dir>" "<Managed dir>/Assembly-CSharp.dll"`, then delete the generated `.csproj`.
  The ilspycmd version is pinned to 9.1.0.7988 because newer releases need a .NET SDK newer than 8.

## Workflow
- Write and build mods here in the repo, and commit them to git. Output goes to each project's `bin\`.
- Deploy to the game only when the user says it's ready for testing. Don't deploy as a side effect of building.

## Build / test
- Build: `dotnet build`, or Ctrl+Shift+B in VS Code. This stays in the repo.
- Deploy: `dotnet build -p:DeployToGame=true`, or the "deploy to game" task in VS Code (Terminal > Run Task). Add a project path to deploy one mod only, e.g. `dotnet build PhotoMode -p:DeployToGame=true`.
- Close the game before deploying a mod it has already loaded, because the DLL is locked.
- Logs: `<GameDir>\BepInEx\LogOutput.log` and `%USERPROFILE%\AppData\LocalLow\GigaPuff\On-Together\Player.log`. The BepInEx console window is enabled.

## Game notes (learned while building PhotoMode)
- Searching `reference/`: shell `grep pattern *.cs` breaks, because the file `-PrivateImplementationDetails-.cs` is read as an option. Use the Grep tool, or `grep -- pattern *.cs`.
- Singletons: `MonoSingleton<T>.I` / `NetworkSingleton<T>.I` call `FindAnyObjectByType` whenever the instance is missing (null on the main menu). Don't call them every frame outside a lobby.
- Input: `InputManager` reads the legacy `UnityEngine.Input` and exposes properties. Patching `TaskManager.IsCancelInputs` to return true zeroes all of them (chat uses this). Enter still gets through and opens chat.
- Camera: Cinemachine 2 (`using Cinemachine`). Disabling the `CinemachineBrain` on `Camera.main` gives you manual control (`SwanController` does this). `PlayerMovementController.SetScreenCameraRotation` handles right-click look, scroll zoom and cursor unlocking.
- Window modes: only `OverlayManager.ResolutionMode == Normal` renders the world directly to the screen. Landscape, Portrait and Desk render into a texture behind UI masks. Keys 1-4 pick Normal, Landscape, Portrait and Desk (`OverlayManager.Update`). All three make the game window a see-through, always-on-top layer over the desktop: Landscape and Portrait ("split screen") show the world in a strip (a third of the height at the top or bottom, or a quarter of the width at the left or right), and Desk ("mini mode") in a small picture. Mod UI is still placed against the whole screen, so parts of it can float over the desktop. Every mode, Normal included, has an eye button (top-right in Normal; `UIManager.ButtonHideUI`, private `_hideUIState`: Open → Hide → Open, with an extra HideCompletely step in Desk) that hides the game's UI, and every mod's UI hides with it (`PanelStack.Hidden`, `PanelStack.GameUIHidden`). Switching modes doesn't reset it. The see-through window is Kirurobo's UniWindowController (`using Kirurobo;`, `UniWindowController.current`): `alphaValue` fades the whole window, and every frame its hit test (`isHitTestEnabled`, the opacity of the pixel under the mouse) switches `isClickThrough`, so turn the hit test off to keep clicks going through. Leaving the world switches back to Normal first (`MainSceneManager`). The game is borderless fullscreen in these modes and keeps running while another app is focused.
- `SettingsController` uses its Canvas `enabled` flag to mean the menu is open, so don't toggle it.
- Name tags and chat bubbles: `TextBubbleController._textBubbleCanvas`.
- Player names: `PlayerController.PlayerNameText` is a TextMeshPro text, and players can put TextMeshPro rich text tags in their names (colours, sizes, gradients...). Unity's IMGUI shows those tags as code, so any mod text with a player name in it goes in a `Shared/TextBox.cs` box: TextMeshPro with the name tag's font, measured and drawn from OnGUI like IMGUI, hidden from LateUpdate. `PlayerNames.ForText` closes tags a name leaves open. The game keeps each player's Steam ID next to their name tag: `PlayerPanelController.PlayerSteamIDs[i]` goes with `PlayerControllers[i]` (EmoteSync's `Game.PlayerName`). Photo Mode hides the game's UI by switching off screen canvases, but skips mod canvases (named with `PanelStack.CanvasPrefix`), which hide themselves while a photo is taken.
- Chat box: not its own canvas. It's several `UIManager` objects (`_messagePanelParent` is the draggable container) on the main UI canvas. `IsMessagePanelHidden` is true when the player has minimised chat. PhotoMode shows it alone by turning the canvas back on and adding switched-off Canvas components to every non-chat sibling. It keeps that canvas's raycasters off, because UI hidden that way probably still catches clicks, so it checks clicks on the chat box (`UIManager.MessageInputField`) itself. Pressing Enter selects the chat box (`UIManager.Update`), and the box sends its message on submit (`TextChannelManager.OnEnterPressed`). Local chat messages and chat bubbles reach players within 5 m (3D): each receiving game compares the position the sender sent with its own (`OnChannelMessageReceived`, `TextBubbleController.ShowTextBubble`). `TextChannelManager.Islocal` is true while the Local tab is selected.
- Scenes and menus: build index 1 is the main menu and 2 is the world (`SceneManager.GetActiveScene().buildIndex`, cheap to check every frame). In the world, every game menu or panel sets `TaskManager.LockState`: `UILock` (pause menu, emote wheel), `UIWalkable` (shop, player status), `UIInventory` (inventory), `UIFishUI` (focus menu, player list, fishing), `Music` (at an instrument or drawing board). `Free` means none is open, including while seated focusing.
- Right-click: while `InputManager.IsMouseButton1` is held, `PlayerMovementController.SetScreenCameraRotation` turns the camera and locks the cursor, then warps it back on release, so an IMGUI right-click ends at the wrong spot. IconBar clears `IsMouseButton1` / `IsMouseButton1Up` for a press that starts on its row.
- Hotkeys: the game uses no F keys. BlueSage uses F8 and Steam screenshots use F12. PhotoMode uses F9 and F1. EmoteSync uses F7 and F6. TeleportSpots uses F5. DeskSnap uses F3. NameDesigner uses F4. OutfitSlots uses F2. QuickHide uses F10. DeskSwarm uses F11, which was the last free F key. Session Manager, Card Designer and Doom Together have no key (their icons open them; `WindowKey` sets one).
- Animations: every player animation is one networked animator int, `AnimState`, set through `PlayerAnimationController` (owner only, via PurrNet `NetworkAnimator`, sent once per tick). Emotes: `EmoteController.SetEmoteAnim(index)`, with the anim value in `GameSettings.EmoteAnimStates`. Focus: `PlayerFocusController.SetFocus` also handles props, desk, camera, timer and seats.
- Mod-to-mod messages: the game never uses Steam lobby chat (`SendLobbyChatMsg` / `LobbyChatMsg_t`), so EmoteSync uses it as a channel that unmodded players never see. Don't use lobby member data for this: changing it makes PurrLobby refresh the whole lobby. The lobby ID is `MultiplayerManager.LobbyCode`. For messages to one player, Steam P2P (the old `SteamNetworking` API) works too: the game only reads channels 0 and 1 (`LobbyRequestManager`'s join requests; it accepts every session request once it has started), so Card Table uses channel 4207 and accepts sessions from lobby members itself.
- Shared clock: `PurrNet.NetworkManager.main.tickModule.syncedPreciseTick`. The host counts ticks and clients re-sync to it using their ping.
- Moving the player: the owner sets `transform.position` (the game does this when you fall off the world). Keep the `CharacterController` on and call `Physics.SyncTransforms()`, because a disabled collider never fires `OnTriggerExit` for area triggers. The player's `NetworkTransform` is owner-controlled and sends the move to everyone on the next tick (as a change from the last value sent). Never call `ForceSync()` on a player: when a non-host calls it, the host relays the move again as a change on top, so other non-hosts see the player go twice as far and turn twice as much (PurrNet's `ForceSyncServer` doesn't reset the host's `_lastSentDelta`). The game never calls it for players. The camera follows `MainSceneManager.PlayerFollower`, whose Y rotation is the camera's turn; set `PlayerVCamera.PreviousStateIsValid = false` to cut instead of glide.
- Focus menu: free focus reads parallel lists in `GameSettings` (land `_focusTypes`, `_animationStates`, `_propTypes`, camera lists and `_isDesk`; water `..Water` lists plus `_waterDlcPropTypes` and `_isSummerDLC`). Seat spots read their own `FocusAreaSettings` asset. Only `PlayerFocusController` reads these lists. Free focus also needs a ground tag from `ConstData.FocusableTagNames` and distance from the music hill. Within a category every animation is used once (checked in the game data, seat lists included), so category + animation identifies an activity and its prop. 23 of the 49 land activities bring out the personal desk (`_isDesk`); at seat spots the same activities use the furniture instead. The activity row has 11 buttons, each wired in the scene to `UIManager.ButtonSetFocus(n)`.
- Gravity and focus: `SetFocus` turns the `CharacterController` off for every focus, and `PlayerMovementController.Update` skips `Fall()` while focusing, so a player who starts focusing in the air floats there. While the focus menu (or another menu) is open, `Fall()` still runs. FocusAnywhere skips it to hold you in the air. The game's ready checks (`TaskManager.IsReadyForAreaFocus` / `IsReadyForFreeFocus`) need `GroundState.Grounded`. BlueSage QoL's Focus Anywhere forces both to true, so mods copy those checks instead of calling them.
- Personal desk: `PlayerFocusController._desk`, a child of the player, so it sits at a fixed spot in front of them and moving the player moves it for everyone. The desk and every focus prop (`_props`: laptop, book, easel, the sleep Zzz effects...) carry PurrNet's `NetworkReflection`, which syncs the GameObject's `active` from its owner, so the owner's `SetActive` shows for everyone (the animation clips don't switch anything on or off). DeskSnap tells a friend is at their desk from their synced `AnimState`, and checks whether their desk object is on. Standing up puts you back at `_preFocusPosition` / `_preFocusRotation`, so set those when moving a seated player. While seated the `CharacterController` is off. Who's at a seat spot: `FocusAreaManager.AreaIndexes[NetworkTransforms.IndexOf(net)]` (-1 for none). Desk parts are `MeshRenderer`s under `_desk`, and an empty accessory slot is switched off. In the Player prefab, held props are children of the hand bones (`mixamorig:LeftHand` / `RightHand`), the headphones of `mixamorig:Head`, all under `AvatarArmature`; placed props sit under `MD_AvatarDefault`, the player, or the floatie.
- Floater and water bed: outfit meshes (`PlayerCustomizationController.Floater` / `WaterBed`) that `SetFocus` switches on for water activities; they carry `NetworkReflection` too. Every player's game picks the `SwimAnimator` state from whether they're on (`PlayerAnimationController.Update`): it lifts `ArmatureParent` 0.88 m (bed 0.9 m) and turns it 360° every 160 s, or not at all when neither shows. Whether floaties spin is each viewer's own setting (`SettingsData.IsFloaterRotate`, read from `DataManager`'s copy); the camera drift while focusing is `IsAutoRotateOff`, read from `SettingsController`'s copy. Being "in water" goes by height (`CheckSwim`, `GameSettings.SwimPosY`), so lifting a swimmer can make the game treat them as on land.
- Instruments: `MusicManager`. Each instrument has 13 keys (0-12). A key's MIDI note is that instrument's octave shift plus the key number. `PlayNoteMaster` / `StopNoteMaster` light the on-screen key and send the note to everyone. The octave arrows (`ShiftOctaveUpMaster` / `DownMaster`) change the octave for the whole lobby. Pressing a key again without stopping it leaves the old note ringing. Music rewards and achievements count time at the instrument, not notes played.
- Saving JSON: don't use Unity's `JsonUtility` for a mod's own classes inside a list or field, because it silently leaves them out (TeleportSpots 0.1.0 saved only `"Version"`). Use Newtonsoft.Json, which the game ships. Store a `Vector3` as plain x, y, z numbers, because Json.NET can't write one directly.
- MIDI files: the game ships Maestro (`MidiPlayer.Run.dll`). `new MidiLoad().MPTK_Load(bytes)` gives `MPTK_MidiEvents`, with note times and lengths in milliseconds.
- Drawing: the easel is automatic. `PlayerFocusController.PaintRoutine` photographs the view and fades it in over 60 seconds. Hand drawing happens on chalkboards and whiteboards (`QuadPainterGPU`): a 320 x 180 grid, 5 chalk colours, and chalk is a shop item that gets used up as you draw. `DrawingManager.ActivateDrawing` moves the `DrawCamera` in front of the board. `QuadPainterGPU.Update` reads the mouse directly, so a mod window over a board needs a patch there or clicks paint the board.
- Setting your name: `PlayerData.Name` (rich text allowed). Closing the ID card (`CustomizationUIController.CloseIDCard`) saves it and, in a world, calls `MainCustomizationController.UpdatePlayerInfo(PlayerData.GetPlayerIdInfo())` (a ServerRpc that relays it to everyone), sets `TextChannelManager.UserName` (chat) and `UIManager.PlayerText`. `GetPlayerIdInfo` sends at most 1000 characters of the name. The ID card copies its name box into `PlayerData.Name` when it closes, so keep `NameInputField.text` in step. Setting a `TMP_InputField`'s `text` from code isn't cut to its `characterLimit` (only typing is).
- Session names: `MultiplayerManager.CreateLobby` creates the lobby with `MainMenuUIController.CreateSessionNameInputField.text`; PurrLobby stores it as Steam lobby data `Name` (case kept), and the lobby list (`LobbyItemController`) and in-game player panel show it with TextMeshPro, so colour tags work. `MainMenuUIController.Update` reads Esc/Enter straight from `Input` (Esc leaves the session list). `MonoSingleton.I` doesn't set itself in `Awake`, so mods catch `MainMenuUIController` / `CustomizationUIController` with a `Start` postfix. The game has its own `FocusType` enum, so write `UnityEngine.FocusType` in IMGUI code.
- Outfits: the game has 3 slots in `PlayerDataZip` (`CustomizationDataIDsDict` / `1Dict` / `2Dict`, item IDs and colour numbers), with `StyleNames` and `SelectedStyleIndex`. Every read and write of the selected slot's outfit goes through the `PlayerDataZip.CurrentCustomizationDataIDs` property, which throws past slot 3 (a save with a bigger `SelectedStyleIndex` won't load without OutfitSlots). `DataManager.LoadPlayerData` (in `Start`, once per game) reads `data.txt` and two backups with `LoadZipDataStatus`, picks one, and sets `DataManager.CustomizationData` (what you wear; spawn sends it) from that property. The save is gzipped Newtonsoft JSON, written by `SavePlayerZipData`, `SaveOldPlayerZipData` and the `SaveBackupZipData` coroutine (also every 180 s in a world). In the outfit screen (`CustomizationUIController`, in both scenes), `ButtonSelectStyle(i)` then `CloseAvatarPanel(true)` is "pick a style and close": it saves, sends the outfit to everyone (`PlayerCustomizationController.ApplyCustomization`) and retakes the ID photo of the screen's preview character. `InitStyleDropdown` runs once, at the end of `Start`. Drinking lemonade (`SetLemonadeHat`) changes and saves the outfit with the screen closed.
- Crash files: on a hard crash Mono writes `mono_crash.<hash>.<n>.json` (same hash = same crash spot; `n` counts up, filling gaps). Its frames are metadata tokens: look them up with Mono.Cecil from `BepInEx\core` (PowerShell 5.1 needs `[Reflection.Assembly]::UnsafeLoadFrom`) and `ModuleDefinition.LookupToken`. The Windows DLLs matched the Mac build's (different MVID, same layout, a call chain that reads through). A frame's `il_offset` is the start of the statement it was running. On the Mac (`"architecture": "amd64"` = Rosetta), the game crashed many times in `BitPacker.ReadBits` while reading a `NetworkTransform` rotation: `ReadBitsWithoutChecks` loads 8 bytes (9 when straddling) through a pointer and masks, read mode keeps no padding, and `PackByteData.Read` makes exact-size arrays, so the last values of every packet are read past the array's end. Hence NetworkCrashFix.
- Flying while seated: while `IsFocus`, `PlayerMovementController.Update` ignores the movement keys and skips `Fall()`, and the game only moves you at stand-up (to `_preFocusPosition`), so a mod can move a sitter every frame. `InputManager.Horizontal` / `Vertical` keep working while seated (eased, rebinding-aware, zeroed while typing). Space stands you up, E is the interact key (chests, instruments, lemonade), F reopens the focus menu. `SetFocus` restarts the camera drift (`StartCameraRotationRoutine`). `FollowScript.Update` (public) moves the camera's follow point to the player; call it after moving them or the camera trails a frame. Area triggers fire on the movement collider, which is off while seated, so flying away leaves the game thinking you're still in the old areas (`PlayerAreaChecker.FocusAreaControllers`, the shop, instruments, chests...) until something sends `OnTriggerExit`. Mod windows with player names: IMGUI always draws on top of uGUI canvases, so a window that mixes TextMeshPro names and IMGUI buttons draws its box on the TMP canvas (DeskSwarm's `WindowCanvas`), not with `GUI.Box`.
- Sessions (learned while building Session Manager): there's no server, the host's game is the PurrNet server (`TextChannelManager.isHost`). A session's settings are Steam lobby data the host sets (`MultiplayerManager.CreateLobby`, PurrLobby lower-cases keys): `Name`, `public` (t/f: the session list searches for `public` = t; the Steam lobby itself is always public type, so friends and invites still see a "private" one), `request` (ask to join), `voice` (read once at join by `VoiceManager.JoinChannelAsync`, so changing it mid-session only reaches later joiners), `count`, `version`, the tags `focus`/`mature`/`chill`/`break`/`modded`, `owner`, and a `timer` the host rewrites every 60 s. Joiners read it fresh (`SteamLobbyManager.OnLobbyDataUpdated` picks request or direct join; Steam invites go the same way), and every member's PurrLobby rebuilds `CurrentLobby` (name included) on each lobby data update. The Steam member limit is the picked size + 1 and `count` matches it; joiners count the session full at limit - 1 members (`JoinByCode`). Ask to join is honoured only by the joiner's game: requests are Steam P2P "JOIN-name" on channel 0 to the `owner`, answered with "ACCEPT" / "REJECT <RejectReason>" on channel 1 (`LobbyRequestManager`; `UIManager.OpenRequestUI` shows one at a time). Bans: `DataManager.BanData.BanServerPlayers` / `BanServerPlayerNicks` (paired by index, saved by `SaveBanData`), checked on join requests and on join (`UpdateOnNewPeopleJoin`); `BanRPC` only asks the target's game to leave (it shows the ban panel; there's no kick screen). After changing the list call `PlayerPanelController.UpdateBannedPanel`, since the game's unban buttons go by position.
- ID card (learned while building Card Designer): `PlayerIDInfo` carries 6 lines (Name, DateOfBirth, HoroscopeSign, Location, AreaOfStudy, FavoriteQuote) as UTF-16 bytes, each cut to 1000 characters, tags included, by `PlayerData.GetPlayerIdInfo`, plus `IDCardColorIndex` (into `GameSettings.IDCardColors`) and `IsGold` (earned; don't touch). Other players' cards show in `TemporaryPhoto` (`Canvas/GameUI/Panel_IDCard`, through `BadWordFilterManager.FilterString`). Your own card page is `CustomizationUIController.IDCustomizationPanel` (both scenes): `ButtonIDCard` fills its boxes only from non-empty saved lines, and `CloseIDCard` copies the boxes back, saves and sends, so a mod that changes a line must set the box too. From the scene data (card canvas units): each short line is a single-line box 1211.7 x 99.9 (text area inset 86 x 13), font 47.93; on your own card it has `characterLimit` 40 (typing only); on the viewer's it doesn't wrap and ends in an ellipsis. The quote is 1211.7 x 245.2 (inset 86 x 83), wraps, `MultiLineSubmit` (Enter submits, so typed line breaks are impossible in the game), no character limit, and `lineLimit` 3: setting its text cuts it to 3 lines (`TMP_InputField.UpdateLabel`), measured from the box's last layout when it's hidden. Every text area has a `RectMask2D`, so nothing spills off the card. TMP's default sprite asset is the game's 42 key icons ("ui btn sprite", no fallbacks), so typed emoji don't show; TMP's EmojiOne (15 smileys) is in Resources at `Sprite Assets/EmojiOne`, so `<sprite="EmojiOne" index=N>` works in any game text. The card font (Fredoka-Medium SDF) is dynamic and falls back to Noto Sans, JP, KR, SC, TC and Thai, so their symbols (hearts, stars, music, weather, arrows, shapes) show.
- Clickable mod windows (IMGUI) don't block the game. TeleportSpots puts an invisible uGUI `Image` on a top canvas under its window, which stops clicks on game UI and scroll zoom (`PlayerMovementController.Zoom` skips when `InputManager.MouseOverUIObject` is set). It also clears `InputManager.IsMouseButton0Down` so world clicks (`ClickManager`, fishing) don't go through.

## Guidelines
- Prefer client-side and cosmetic mods. Avoid anything that changes the economy, tickets, achievements or other players' state in shared lobbies.
